# Strata Fork Scaling · E02 и E02-R
Материалы для независимого ревью. Срез 25.11.2026 22:36 +0300. Модель Inkling-2-Mini SQ-10, Apple M4 Max, Metal, два слота, KV в FP16.

## Исследовательский вопрос

Меняет ли восстановление снимка оценки следующего токена? При смене группировки GPU сам движок может выдавать немного другие числа. Поэтому восстановление сравнивали с независимым пересчётом при одинаковой группировке, а влияние смены группировки измеряли отдельно в обоих режимах.

## Три результата

1. **Исходный E02.** Один из четырёх вариантов продолжения вышел за первоначальный допуск при разных расписаниях. Выбранный токен совпал у всех четырёх. При выравнивании расписаний побайтно совпали 16/16 пар. Подробности и отдельное исправление удержания памяти описаны в [отчёте E02](reports/CORRECTNESS.md).
2. **Первичная независимая проверка E02-R.** Восемь деревьев использованы для калибровки только на штатной Strata, четыре других — для независимой оценки после фиксации критериев. Все условия выполнены. Побайтное совпадение при одинаковой форме исполнения — 224/224 пар полных векторов, по 200 058 логитов на вектор. Эффект смены размера пакета при decode совпал по всем пяти метрикам со снимком и при пересчёте. [Протокол](E02-R.md) · [Первичный отчёт и график](reports/E02-R.md)
3. **Дополнительная независимая проверка.** На момент выгрузки побайтно совпали 336/336 пар на завершённых деревьях. В первой дополнительной группе исходный предел JS оказался превышен уже у штатной Strata при смене расписания на первом предсказании. Этот предел не воспроизвёлся на новых данных. Установить дефект восстановления по этому превышению нельзя. Границы сохранены.

- cohort-001, деревья 49101, 49102, 49103, 49104. Решение по протоколу — native_out_of_envelope. native / js на шаге 0 — 0.00093571145 при границе 0.00049962104. candidate / js на шаге 0 — 0.00093492695 при границе 0.00049962104.
- cohort-002, деревья 49105, 49106. Группа ещё измеряется.

## Что можно заключить

Строгая проверка поддерживает корректность переноса состояния в измеренных путях. Численная эквивалентность между разными расписаниями по всем установленным границам пока остаётся открытым вопросом. Длинные ветки получили по 1024 заранее заданных токена. Логиты зафиксированы на восьми глубинах; свободная генерация и промежуточные распределения между срезами остаются за пределами вывода. Единица независимой проверки — дерево. Несколько срезов одной ветки зависимы.

## Как проверить

- [Машиночитаемые показатели](reports/E02-R-metrics.json) содержат максимальную абсолютную ошибку, RMSE, JS-дивергенцию, совпадение top-10 и greedy. [Калибровочные границы](runs/E02-R/freeze.json), [запечатанные входные данные](runs/E02-R/calibration-seal.json), [старт независимой проверки](runs/E02-R/holdout-start.json) и [первичный вердикт](runs/E02-R/gate.json) позволяют проверить последовательность фиксации правил.
- Для проверки дополнительной группы откройте её gate.json в runs/E02-R/extension. Там приведены фактические значения и пределы для каждой метрики. В каталоге hold каждой выборки файлы matched-*.json содержат попарные сравнения. Для незавершённой группы в выгрузку вошли только полностью измеренные деревья.
- Методика и код измерений находятся в tools, изменения движка и идентификаторы сборки — в archive. В отдельном архиве E02-R-logits.zip лежат исходные массивы NumPy в FP32. Запись raw в каждом result.json содержит исходный локальный путь. Отбросьте часть до e02r-logits/ включительно и найдите оставшийся путь в архиве массивов. SHA-256 массива указан там же в поле sha256. Модель и исполняемый файл для GPU-прогона потребуются отдельно; пересчитать метрики из готовых массивов можно на CPU.
