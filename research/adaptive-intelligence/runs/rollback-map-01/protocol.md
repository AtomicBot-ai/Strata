# Карта откатов, 25 ноября 2026

Вопрос: существуют ли ошибочные черновики, где повторная генерация с начала шага даёт правильный ответ при неудаче нового старта? Это отладочный эксперимент с перебором точек и последующей оценкой. Способность движка выбрать точку заранее в нём не проверяется.

- Выборка — первые ID в порядке SHA-256 от rollback-map-v1/ID внутри каждой страты. Три целочисленные задачи MATH-500 уровня 4, три уровня 5, две средние и две трудные задачи AtCoder из тех же трёх публичных диапазонов LiveCodeBench v6. Исключены все ID предыдущего эксперимента, в том числе его holdout. Все новые ID и условия зафиксированы в tasks.json до генерации.
- Один черновик на задачу (seed 719), модель Inkling SQ-10, температура 1, top-k 32, top-p 0,95, три явно обозначенных шага и финальный ответ. Во всех запусках один и тот же шаблон с началом видимого ответа «Step 1:». Инструкция задавать шаги может сама менять результаты относительно прошлого пилота.
- Для всех неверных или незаконченных черновиков сравнить новый старт и возврат к каждому найденному заголовку Step 2/3 на точной границе токена. Сохраняются только более ранние шаги и заголовок следующего; его текст генерируется заново. Для оборванного по лимиту черновика есть контроль «продолжить с конца». Завершившийся неверным ответом черновик остаётся исходным отрицательным контролем.
- Каждая точка получает одни и те же три seed: 1301, 1303, 1307. Лимит 448 новых токенов на попытку. Начинаем в пустом слоте Strata, подавая сохранённые ID как внешний префикс. Отдельно оцениваем результат, доступный до 448-го токена полного ответа с учётом сохранённого префикса. При двух точках отката добавляем ещё три независимых старта (2300–2302), чтобы поиск лучшей точки не получил больше попыток, чем контроль. Контроль продолжения полного черновика учитывается отдельно.
- Оценщик передаёт драйверу только ID неудачных черновиков. Следующие генерации получают публичное условие и префикс. Эталонные целые числа и ожидаемые результаты скрытых тестов доступны оценщику. Python выполняется в изолированном контейнере. Невозможность извлечь финальный ответ отмечается отдельно от неверного извлечённого ответа.
- Различаем единичную парную победу (тот же seed), успех точки при нуле успешных рестартов с тем же числом попыток и сохранение успеха при равной полной длине. Публикуем все строки, включая проигрыши и отсутствующие границы. Множественный перебор точек даёт верхнюю оценку, подбор лучшей точки по скрытому эталону нельзя использовать как рабочий селектор. Бюджет опыта до двух часов.
