# Checkpoint experiment — frozen before observing task answers

Inkling SQ-10, M4 Max, FP16 KV, no draft, maximum context 4096. First two debugging IDs, next up to four pilot IDs, one held back per domain in SHA-256 order (see prepare.py). Integer MATH answers at levels 1–4, easy/medium AtCoder stdin tasks from complete records in three byte ranges of LiveCodeBench release_v6 test6. The pilot is a convenience sample, not the full benchmarks.

Four modes: serial native replay with same-slot prefix caching; native two-slot batched first wave; native independent samples from the original prompt; sequential checkpoint siblings. For the three tree modes the first 24 sampled tokens at seed S form the anchor, or EOS returns the original answer. This fixed token boundary avoids a hand-picked step. Continuations use S+1 onward. Source engine saves only tokens already processed, including all but the terminal sampled anchor token. GEN reconstructs repetition history and starts an independent RNG stream. The same warm engine build handles all modes.

Per task/seed allow 2*(input length + 320)+24 forwarded tokens, including prefill and rejected attempts, up to four candidates. Last generation may be truncated by the remaining budget. Reserve a common 20 GiB model+runtime allocation ceiling on the 48 GiB Mac; record Metal TotalAlloc and checkpoint payload separately from process peak footprint. Inspect native cache reuse and require declared budget adherence. Random seeds 101,211,307; rotate mode order across seeds. One seed on debug. No quality thresholds tuned on pilot. Time cap for debug+pilot+grading is two hours. Save all completions including incomplete and failed ones.

Selector: math uses plurality of extracted final integers with ties resolved by earliest candidate; code uses number of passing public examples with earliest tie. No answer key in the search or selector. Private code tests only for scoring; numerical math equality against exact integer key. Report selected accuracy vs strongest wrapper selected separately by domain on debug, oracle on pilot, paired gains/losses, wall time (including selection), effective processed tokens and memory. An equal-time read uses only completions and public checks that fit a common task-wise wall allowance, and is labeled retrospective. +5 percentage points and a paired task-level 95% interval above zero would motivate confirmation; this small pilot alone cannot establish generality.

External arm is chosen on debugging tasks by highest selected accuracy, then lowest mean end-to-end time, then name. All three wrappers are also reported individually. For retrospective equal-time scoring, allow the shorter of the two actual task/seed runtimes, re-select among candidates available by that instant, and charge standalone public checking latency (reuse identical candidates within an arm). No intermediate predictions are streamed to an external service.
