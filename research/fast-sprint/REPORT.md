# Atomic Turbine · одиночная генерация на Metal

26 ноября 2026 · Apple M4 Max, 48 ГиБ · macOS 27.2.1. Исходная ревизия релизного ZIP — `61d705eb19b0037605641cc294d0db5e844bc889`, SHA-256 архива — `e9267ea44bff7865e4bac0a4a45148db971b724269a3fc05d6ef24b4f77983da`. Коммит `ada02086` фиксирует приёмку пакета. Базовая Strata — `b28ca95e`, тег приложения v0.2.22. Числа ниже относятся к локальному пакету и диагностической сборке из тех же исходников. [Публичный релиз Strata](https://github.com/Niko1221/Strata/releases/tag/v0.2.22).

## Условия

Один процесс на вариант, один запрос за раз через штатный протокол stdin/stdout. Короткий прогрев на отдельном тексте перед двумя измерениями. Фиксированные задания продолжить словарь Python и дневник экспедиции. Для Inkling — текстовые продолжения. Для основной серии Qwen — шаблон пакета с выключенным thinking. Одинаковые token ID входа, seed 83101, temperature 0, без штрафов, штатные правила завершения. Ограничение 128 выходных токенов у Inkling и 64 у Qwen. Контекст движка 2048, в отдельном опыте с состоянием 17000. Файловый кеш macOS сохранялся между запусками. Прогресс соседней сессии имеет приоритет. При появлении другого процесса Strata или сборки наблюдатель прерывает наш замер.

Время запроса начинается перед записью GEN, TTFT заканчивается при первом T. Скорость выдачи после prefill равна числу последующих токенов, делённому на время от первого T до DONE. Показатель включает draft, verify и восстановление. Для 128 выданных токенов числитель равен 127. Пик памяти — пиковый physical footprint всего процесса по macOS, включая прогрев. В JSONL записаны команды, SHA бинарника, входные и выходные ID, сырые кадры DONE, TTFT, время и счётчики. Сопоставление двух ответов выполняется по всем ID, включая длину. Прогревы исключены из выводов.

## Результаты

**T01 · ForkSpec — DROP для узкого дерева и полного снимка на каждом шаге.** На Inkling SQ-10 встроен DSpark. Штатный Metal verifier подстраивает глубину по принятым токенам, использует кольцо состояний ShortConv при линейной проверке и фиксирует только принятый путь при ветвлении. Продуктовый STATE_SAVE для веток требует FP16 KV и выключенного DSpark. Частная сборка меняет верхнюю границу дерева с 10 до 6 узлов. Глубина по-прежнему ограничена штатной политикой. Сэмплер и правило приёма токена общие у обоих вариантов.

| Inkling, запрос | Без draft | ZIP с DSpark | Контроль 10 → кандидат 6, ток/с | TTFT и пик, 10 → 6 | Совпадение ID |
|---|---:|---:|---:|---|---|
| Код, вход 1004, выход 128 | 58,45 | 101,03 | 101,01 → 106,02 (+5,0%) | 1,66 → 1,66 с, 2,44 → 2,44 ГиБ | Все 128 совпали во всех режимах |
| Текст, вход 1280, выход 128 | 56,78 | 41,87 | 41,90 → 42,19 (+0,7%) | 2,13 → 2,13 с, 2,60 → 2,60 ГиБ | Оба дерева совпали с ZIP. Первый разрыв с no-draft на токене 30, 151483 → 151537 |

Штатный `--draft-adapt` из ZIP дал 101,02 ток/с на коде и 50,78 на тексте в отдельном контроле. Узкое дерево на тексте медленнее этой доступной политики. Адаптивный режим также разошёлся с no-draft на токене 30. Причина численного расхождения не установлена.

Одна пара A/B, флаг трассировки выключен для обеих сторон. Следующие повторы остановлены после проверки токенов. В отдельной трассировке штатного дерева на коде было 23 проверочных прохода, draft / verify / работа с состоянием заняли 149 / 1101 / 1,2 мс за 1253 мс выдачи. На тексте — 76 проходов, 417 / 2592 / 14,4 мс за 3027 мс. Время работы с состоянием включает snapshot, восстановление после отказа и commit принятого пути там, где они выполнялись. Даже полное устранение этих операций сэкономило бы менее 0,5% времени на каждой из двух нагрузок. Единственный прогон без DSpark предшествовал обнаружению соседнего процесса, его скорости приведены только как ориентир. Вывод об узком дереве основан на паре под наблюдением.

**T03 · SSD Speculation — DROP для окна 3.** Qwen3.8-Flash-Next GSQ-RCO IQ3_XXS, DFlash2 Q4_0 с BF16 selector, Metal expert arena 6,00 десятичных GB. Движок подтвердил работу SSD streaming, DFlash2 и отсутствие MTP. Основной контроль — `--spec 6 --draft-conf 0.5 --suffix-draft 3`. Штатная коррекция по уверенности и поиск продолжения в запросе работают в обоих вариантах. Меняли только `--spec 6` на `--spec 3`. Без драфтера поиск продолжений выключен. Последовательность пар A/B, B/A, A/B, свежий процесс на сторону, 64 выходных ID во всех основных ответах.

| Qwen, запрос | Без draft, ток/с | Окно 6 → 3, медианы ток/с | Изменение TPS по парам | Δ чтений disk0 на токен, медиана пар | TTFT / wall, медианы, с |
|---|---:|---:|---|---:|---|
| Код, вход 97 | 10,07 | 14,60 → 12,59 | −18,5%, −13,1%, −12,6% | −3,4% | 3,25 / 7,57 → 3,28 / 8,38 |
| Текст, вход 129 | 8,23 | 9,65 → 9,82 | +4,9%, −3,2%, +1,8% | −0,4% | 3,82 / 10,43 → 3,88 / 10,29 |

На коде число раундов выросло с 12–13 до 21–27, число принятых черновых токенов на раунд упало с 3,92–4,33 до 1,37–2,05. На тексте — с 26 до 29–30 раундов. Полное время decode на раунд уменьшилось, но пришлось чаще запускать модель. Медианный пик обеих конфигураций около 15,08 ГиБ. Все 12 основных ответов совпали с соответствующим жадным эталоном по всем 64 ID. В первом диагностическом опыте без обёртки чата текст закончился одним EOS. Диагностические строки, прерванный из-за чужого процесса запуск и остановка его координатора исключены из таблицы.

Физические чтения измерены для всего disk0 от первого токена до DONE, на 63 последующих токена. На коде медианы 226,0 → 220,1 десятичных МБ/токен, на тексте 307,0 → 305,7. В контрольные 250 мс перед запросом наблюдалось до 8,9 МБ фоновых чтений. Время чистого GPU verify Qwen отдельно не измерялось. По системному счётчику нельзя приписать каждое чтение экспертам. Порог экономии I/O 15% не достигнут.

**T02 · StateDelta — DEFER.** В отдельном опыте на ZIP прогрели родителя до 16 384 токенов, сохранили его из слота 0 и дважды восстановили в слот 1. Payload составил 708 542 464 байта (675,7 МиБ), создание заняло 43,74 мс, восстановления — 55,29 и 11,26 мс по протоколу. Последующие четыре токена совпали при обоих воспроизведениях. Это единичные задержки, включая доставку команды. Полный снимок переносит заполненные KV-строки и ShortConv в независимое хранилище. Простое разделение этих буферов позволило бы следующей ветке перезаписать родителя. Повторяющейся лишней полной копии на пути обычного decode аудит не показал. Для удаления основной копии понадобилось бы отдельно реализовать владение изменяемыми страницами или восстановление по журналу.

## Решение

Новую политику в RC не включаем. Для следующей версии рекомендуем сохранить штатное окно DFlash2 6 с prompt lookup как контроль на Flash-Next IQ3_XXS при арене 6 GB. На этих заданиях это уже даёт 14,60 и 9,65 ток/с против 10,07 и 8,23 в единичном контроле без drafting. Перенос результата на другие запросы и конфигурации требует отдельных данных.

В этом спринте не проверены обычный стохастический sampling, причины расхождения Inkling в логитах, 8–16K single-stream decode, отдельные сценарии принудительного отказа и отмены с последующим запросом. Производственного кандидата для интеграционного fork smoke не осталось. Для T02 выполнено собственное восстановление двух продолжений. Полный suite и aggregate verify не запускались.

## Воспроизведение

Рабочий каталог — внешний `turbine-intelligence`. Распаковать указанный ZIP в `.work/fast-sprint/`, получить исходники движка командой `git -C Atomic-Turbine archive 61d705eb engine` и распаковать их в `.work/fast-sprint/source/`. Из этой копии применить `patch -p1 < ../../../research/fast-sprint/inkling-experiment.patch`. Собрать единственную цель:

```sh
cmake -S .work/fast-sprint/source/engine/src/inkling2 -B .work/fast-sprint/build -DCMAKE_BUILD_TYPE=Release
cmake --build .work/fast-sprint/build --target strata-inkling --parallel 1
```

Запуск одного варианта — `.work/rc/venv/bin/python -B research/fast-sprint/run.py FAMILY MODE LABEL`. Для основной серии Qwen добавить `--chat`. Для Inkling использовать MODE `off`, `stock`, `adapt`, `trace`, `tree`, `narrow` или `state`. Для Qwen — `off`, `stock` или `narrow`. Для LABEL взять новое имя, сырые строки дописываются в results.jsonl. Пути к уже установленным весам и токенизаторам указаны в run.py. Для Qwen используется штатный упаковщик из ZIP с локальными `model.safetensors config.json .work/fast-sprint/qwen-dflash2.pack --q4_0`. SHA-256 полученного DF2P совпал с эталоном Strata, `cda40d62d0eb8f37ed6e272142641a1d2f0de4a32f9e14d0416e7a71534849f1`. Для чтений disk0 используется уже собранная библиотека проекта `.work/ssd-counters.dylib`.

Результаты и воспроизводимый исследовательский патч находятся рядом с этим файлом. Экспериментальные переменные `TURBINE_NARROW_TREE=1` и `TURBINE_TRACE_VERIFY=1` действуют только в частной сборке, наличие переменной включает соответствующий режим.
