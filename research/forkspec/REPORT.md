# ForkSpec и AdaptiveSpec · 26 ноября 2026

**Решение для alpha — сохранить штатные настройки.** На коротком Inkling-префиксе родитель и ребёнок после native restore выдали одинаковые 32 токена при работающем DSpark. На длинном префиксе обнаружен воспроизводимый дефект линейного rollback. **F02 — DEFER до исправления rollback, F03 — пропущен по условию корректности. F01 — DEFER:** преимущество четырёх стартовых шагов на повторяющемся словаре почти исчезло на новой задаче программирования.

## F02. Какой контракт проверен

Исходный HEAD — `90ebd75b51210c85fdfcd2854f34bf7ddb41109c`. Все правки сделаны в двух экспортированных копиях. Пока шли опыты, основная ветка перешла на `49a60a5f`; в этом переходе изменился только отчёт Flash-Next. Git-объект дерева `engine/` одинаков — `c759567e332564c29f15f4bf1988df5d8f323e29`. Сборка, ветка и рабочие файлы соседней сессии использовались только для чтения. Патч кандидата предназначен для воспроизведения; в продукт его не переносили.

Нативный сервер принимает SAVE/RESTORE только для свободного слота, хранит один process-local handle и его committed token IDs. Следующий запрос передаёт суффикс и получает свой RNG. Последний выданный, ещё не обработанный моделью токен не входит в снимок. В существующем HTTP родитель готовится командой `BGEN … 0`, конфигурация и префикс проверяются при выдаче lease. Обычный launcher Inkling явно выбирает `--draft off`. Точки входа на исходном SHA — `engine/src/inkling2/ink_serve.h:574,620,779`, `terminal/serve/turbine_state.py:68,137`, `terminal/serve/server.py:7511,8528` и `atomic/atomic-turbine:66`.

Исследовательский флаг `TURBINE_FORK_DSPARK=1` совместно с положительным `TURBINE_SNAPSHOT_MIB` открывает путь на Metal FP16 с одним или двумя слотами без vision. Патч дополняет INFO и существующий HTTP-ответ полем `fork_dspark`. Кандидат сохраняет физические строки K и V всех 48 target-visits, четыре истории ShortConv, K/V всех трёх слоёв DSpark (включая глобальный слой), последний committed `dsp_frnn_slot` и token IDs. Позиция следует из числа IDs; слоты используют один layout и веса в пределах процесса. Длина каждой копии и смещение назначения считаются по stride конкретного буфера. Эти байты входят в cap. Restore сбрасывает прежнюю историю назначения и его метаданные tree/verify, затем устанавливает сохранённые данные. Временные строки дерева и sampler между запросами не переносятся. GPU завершает граф до копирования. Исходные реализации — `metal/ink_metal_backend.mm:163,174,202,264`, `metal/ink_metal_runner.h:429,526,2125,2360` относительно `engine/src/inkling2/` и `engine/metal/src/mtl_rt.mm:479`. **Первый контрпример.** Проверка обработала позиции 1037–1044. После отклонения первой подменённой drafter-гипотезы следующая позиция — 1038. Физическая строка для 1044 совпадает со старой позицией 20 у target (кольцо 1024) и 19 у drafter (кольцо 1025). Обе старые позиции ещё видны следующему шагу. На одном SWA-слое каждого из двух путей наблюдатель сравнил K до проверки и после возврата из штатного rollback. В каждом изменились 1024 из 1024 FP16-значений. Изменение предложения сделано **до** обычной проверки целевой моделью. Контрпример показывает повреждение исходного состояния до SAVE. Сравнение токенов родителя и его копии само по себе его пропускает. [Журнал кольца](ring.log) · [Результаты с token IDs и хешами логитов](results.jsonl)

Механизм виден в исходниках. Линейная верификация пишет KV непосредственно в физические кольца; `restore_verify_step` восстанавливает ShortConv и f_rnn. Чтение следующей позиции по-прежнему адресует подменённую строку. См. `metal/ink_metal_ops.metal:708,787`, `metal/ink_metal_dspark.metal:97,217`, `metal/ink_metal_runner.h:827,1985`, `metal/ink_metal_backend.mm:520`. Для допуска нужен откат перезаписанных живых строк либо проверка в отдельном буфере с записью только принятого пути. Также требуется проверить видимость будущих строк внутри самого пакета верификации. Это изменение контракта backend; расширение snapshot не может восстановить уже потерянные данные.

**Граница результатов.** Для F03 отсутствуют makespan и сравнение D/C или D/B — измерительный допуск закрыт. HTTP-поле проверено по коду; живой HTTP/OpenCode smoke, параллельная клиентская операция, sampled distribution, 16K fan-out и длительный тест удержания памяти не запускались. Короткие native-проверки выше не заменяют эти случаи. Полные тестовые наборы и aggregate verify не запускались.

## F01. Стоимость шага и расписание

Один Release-бинарник для четырёх arms. A — заводская оценка; B — измеренная per-request EMA со штатным fallback; C — заводская оценка и четыре однотокенных шага; D — EMA и те же четыре шага. Счётчики сбрасываются при admission. Образец берётся на обычном синхронном шаге после sampling или в явном пути fused cooldown, до освобождения слота. Первый обычный шаг запроса исключён из EMA. Штатный внешний governor работает во всех четырёх режимах. В C/D задействован его существующий путь калибровки, поэтому результат относится к расписанию вместе с калибровкой. Маркеры проверены в отдельном запуске. [Экспериментальный diff](factor.patch) · [Маркеры четырёх ordinary forward на запросе №2](factor-markers.log)

M4 Max 48 GiB, macOS 27.2.1, питание AC, lowpowermode 2; Metal, Inkling-2-Mini-SQ-10, FP16 KV, один слот, context 2048, chunk 128, greedy, seed 83101. Каждый процесс получает один и тот же прогрев на 8 токенов, затем словарь (1004→128), текст (1280→128), новую задачу восстановления JSONL-журнала с оборванной последней строкой (122→256). Порядок A/B/C/D, затем D/C/B/A. В ячейках ниже среднее двух запусков: decode TPS после первого токена и секунды всего запроса с prefill, probes и cooldown.

| Режим | Словарь, TPS / с | Текст, TPS / с | JSONL, TPS / с |
|---|---:|---:|---:|
| A | 100,62 / 2,928 | 51,98 / 4,589 | 93,09 / 2,990 |
| B | 100,73 / 2,930 | 52,73 / 4,560 | 93,13 / 2,984 |
| C | 116,81 / 2,744 | 53,09 / 4,543 | 92,97 / 2,983 |
| D | 117,69 / 2,738 | 55,27 / 4,408 | 93,20 / 2,974 |

На словаре C/A даёт +16,1%, D/C ещё +0,8%. Число speculative rounds упало с 23 до 16; в A выдано 127 токенов этими раундами при 104 принятых предложениях, в C — 122 при 106 принятых. Переключение оценки почти не влияет на этот результат. На тексте D/A даёт +6,3% decode, но продолжения различаются. На новой задаче D/A даёт +0,12%; проверочная третья пара A/D дала 93,53/93,23 TPS и 2,965/2,972 с. В A/B для этой задачи было ноль обычных шагов после prefill. Оценка B осталась на fallback, поэтому сравнение B/A здесь не измеряет разницу между 17 и 41 мс. Максимальный process peak footprint в двух блоках — 2,60 GiB; это показатель macOS для процесса, модель на диске занимает 10 471 526 400 байт.

Словарь совпал по всем 128 IDs с adapt и plain. На тексте A/B совпали друг с другом, C/D разошлись с A на токене №30 и с plain на №46. На JSONL все четыре arms совпали по 256 IDs, первое отличие от plain — №15. В одном forced replay общего префикса текста A и D выдали один ID 151537. Одношаговый контроль не устанавливает причину расхождения при свободной генерации. Измерения скорости не подтверждают lossless. ## Воспроизведение

Команды выполняются из корня `turbine-intelligence` в локальном окружении с Metal, существующими весами, подготовленным Inkling tokenizer и Python окружением прошлого спринта. Из ZIP распаковать дерево с сохранением относительных путей. Для свежей копии использовать новый каталог. Результаты можно писать отдельно от приложенных. Полученные SHA-256 весов и всех трёх исполненных бинарников сохранены отдельно. F01 занял 152,1 с суммарного времени процессов с прогревом, диагностикой и контрольной парой. Семь процессов F02 заняли около 29 с. [Происхождение и хеши](provenance.json)

```sh
w=$(mktemp -d "$PWD/.work/forkspec-replay.XXXXXX")
mkdir -p "$w/native" "$w/factor"
git -C Atomic-Turbine archive 90ebd75b engine terminal/serve | tar -x -C "$w/native"
git -C Atomic-Turbine archive 90ebd75b engine | tar -x -C "$w/factor"
patch -d "$w/native" -p1 < research/forkspec/candidate.patch
patch -d "$w/native" -p1 < research/forkspec/observer.patch
cmake -S "$w/native/engine/src/inkling2" -B "$w/build" -DCMAKE_BUILD_TYPE=Release -DCMAKE_CXX_FLAGS=-DTURBINE_TEST_LOGITS
cmake --build "$w/build" --target strata-inkling --parallel 1
export FORKSPEC_RESULTS_DIR="$w/results" FORKSPEC_BINARY="$w/build/strata-inkling"
.work/rc/venv/bin/python -B research/forkspec/native_check.py short draft-off disabled budget
# Ожидаемый ненулевой код выхода на обнаруженной порче кольца.
.work/rc/venv/bin/python -B research/forkspec/native_check.py ring
```
