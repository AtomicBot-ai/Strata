# Когда Flash-Next выигрывает от общего контекста

**На ревью · 26 ноября 2026 · Atomic Turbine v0.1 alpha**

На RTX 5090 Laptop четыре одновременных вопроса по одному документу завершились за **54,72 с** с автоматическим снимком и за **150,86 с** со штатным кешем. По медианам трёх парных прогонов выигрыш составил **96,14 с (63,7%), или 2,76×**. Первый полный ответ в медиане пришёл на **1,78 с позже**. Преимущество в этом сценарии получил пользователь, которому нужны ответы на все четыре вопроса.

## Что делали клиент и движок

Клиент отправил четыре обычных запроса в `/v1/chat/completions`. Каждый содержал одну и ту же карточку релиза и отдельный вопрос про владельца, порт, регион или лимит повторов. Ожидаемые ответы — `Atlas`, `8080`, `Dublin`, `3`. Специальных заголовков клиент не передавал.

В обоих режимах запросы обслуживали два слота, штатный кеш был включён. В режиме снимка движок резервировал третий слот для состояния модели после обработки общей истории. Первый запрос сохранял это состояние, следующие три могли начать с него при точном совпадении начальных токенов. Если клиент меняет системную инструкцию до документа, одного совпадения текста документа для восстановления всего снимка недостаточно.

## Результаты на CUDA

Время отсчитывали от отправки четырёх запросов до получения полных ответов. Загрузка модели и прогрев завершались до старта таймера.

| Пара | Какой режим запускали первым | Все 4, штатный кеш | Все 4, кеш + снимок | Ускорение |
|---|---|---:|---:|---:|
| 1 | Штатный кеш | 162,57 с | 54,72 с | 2,97× |
| 2 | Кеш + снимок | 150,86 с | 54,91 с | 2,75× |
| 3 | Штатный кеш | 146,64 с | 54,51 с | 2,69× |
| **Медиана времени** | | **150,86 с** | **54,72 с** | **2,76× по отношению медиан** |

- **Первый полный ответ.** Медианы составили 41,93 с и 43,71 с соответственно. Порядок менялся между прогонами, поэтому разницу 1,78 с нельзя считать фиксированной стоимостью сохранения.
- **Повторное чтение.** В каждом прогоне со снимком журнал движка зафиксировал одно сохранение 154 токенов и три восстановления по 154. Это 462 повторно использованных токена на четыре вопроса. Со штатным кешем клиент во всех трёх прогонах получил ноль кешированных токенов для этих вопросов.
- **Ответы.** В каждом режиме 12 из 12 ответов прошли проверку по ожидаемому значению. В обоих режимах модель сгенерировала по 36 выходных токенов суммарно. [Данные по всем шести прогонам и каждому ответу](results/qwen-rtx5090-http-fanout.json)

## Какие выводы применимы к продукту

**Порог по умолчанию — 2048 токенов.** Для этого короткого бенча порог снизили до 64 в обоих режимах. История из 154 токенов при настройках поставки не достигла бы порога. На Mac из распакованного ZIP при штатном пороге второй запрос показал 2261 кешированный токен. Этот счётчик включает все виды кеша. Парного замера времени для него нет.

**OpenCode 2.0.24 работает без плагина.** На M4 Max пользователь выбрал `turbine/qwen` и поручил субагенту прочитать порт из файла. Клиент вернул `8080`. Даже при сниженном до 32 токенов пороге движок зафиксировал пять автоматических сохранений и **ноль восстановлений из резервного слота**. Штатный кеш обслужил часть запросов. Время этой задачи в двух режимах не сравнивали. Для AMD HIP пока нет сборки и проверки на Radeon. [Данные OpenCode, Metal и CUDA](results/qwen-auto.json)

**Предлагаемая формулировка для релизных заметок:** «В тесте Flash-Next на RTX 5090 Laptop с порогом снимка 64 токена четыре параллельных вопроса с общей историей завершились за 54,7 с вместо 150,9 с». Для оценки выигрыша по умолчанию нужен тот же парный замер с общим началом длиннее 2048 токенов. Для заявления об ускорении OpenCode нужен замер реальной задачи с подтверждёнными восстановлениями.

## Как воспроизвести

Использован один бинарник Qwen3.8-Flash-Next IQ3_XXS из коммита `d53a525a`, CUDA 12.9, Ubuntu под WSL2, RTX 5090 Laptop с 24 463 МиБ видеопамяти. HTTP-шлюз работал на Mac, связь с движком в обоих режимах шла через SSH. Перед каждым из шести прогонов запускали новый процесс и прогревали его посторонним запросом. Кеш файловой системы между запусками не очищали.

Подготовьте два рабочих JSON-профиля одного и того же движка с одинаковыми путями к весам и токенизатору. Для первого задайте `TURBINE_QWEN_FORK=0` и `--batch 2`, для второго — `TURBINE_QWEN_FORK=1` и `--batch 3`. В обоих использовались `--prompt-cache-root 64`, контекст 512, `--expert-cache 64` и 512 МиБ для кеша отложенных диалогов. Полные аргументы и SHA-256 бинарника сохранены в данных прогона.

Из корня репозитория с установленными зависимостями шлюза выполните:

```sh
python atomic/bench/qwen_http_fanout.py off.json on.json ./fanout-results
```

Скрипт проверяет число доступных слотов и сохраняет ответы, время и события движка для каждой пары. [Сценарий бенча](qwen_http_fanout.py)
